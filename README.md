# 巡检网关、班次计划与船务交班

本地资料使用虚构的测线、设备和船班。网关目录、即时领取和船务台共用演练轮次，值班员可以独立推进。设备信息、工程工单和船务凭据各有自己的数据范围。运行使用 Python 3.11 标准库。

```sh
python3 source_service.py --port 8040
python3 -m unittest discover -s tests -v
```

## 值班服务

`duty_service.py` 是值班的接收端：按轮次从演练台领取原件、判定覆盖、安排并跟住船次，状态写入本地文件，关掉再打开能接着走。

```sh
python3 source_service.py --port 8040 &
python3 duty_service.py --source http://127.0.0.1:8040 --port 8050 --state duty_state.json
```

演练台推进轮次后调用 `POST /tick`，本服务会同步轮次、应用工程撤回与现场补证、执行本轮领取、调整船务并记录错过窗口。查询接口：

- `GET /status`、`GET /sections`、`GET /sections/{id}`：区段当前证据、待核读数与待补页；
- `GET /trips`、`GET /trips/{slot}`：船次已确认安排、待变更申请与交接快照；
- `GET /audit/{id}`：哪次领取、哪份校准、哪条派工决定了眼下安排；
- `GET /missed`：错过复核窗口的原因；`GET /notes`：已保全但来不及参与的原件去向；
- `POST /qc`：质检否定特定原件（`{"original": "世代|页|封版"}`）或测线（`{"line": "T1"}`），`"undo": true` 撤销；其他范围已有覆盖继续可用。

实现的要点：原件以世代、页、封版标识，两次领取内容核对一致才凑成完整原件；每次传输开始即占本轮余量，换版、不可取、越界都计入用量；排队先保仍可能决定复核窗的资料，再处理无法重领的原件，同等以较早失效为先；目录粗范围只决定是否值得领，覆盖只由校准后的读数与现场补证构成；读数可能位置横跨格点或区段时先待核；新封版显式顶替当前证据，旧期原件保留解释旧单；预约未锁定随证据即时调整，锁定后只提交变更申请且旧安排仍占容量，出发时冻结交接记录；回执丢失按请求号对账，不重复占船也不重复释放。

## 时间与页目录

`GET /` 提供当前轮次。演练台用 `POST /round` 发送 `round` 整数轮次，只能向前。重新启动接收端不清空来源状态。只有结束整场演练后重新运行本服务才回到第 0 轮。

`GET /directory` 返回公开范围内的历史目录条目，包含架次 pass、页码、设备类别、设备世代、线路修订 line、封版、原件字节数、沿线路粗范围 rough 和各链路的片段要约。要约里的 from 含当轮，until 不含当轮。目录是计划依据，已下传原件与实际领取情况可能领先目录。两个链接每轮各有 capacity 和 spent（字节）。0 额度意味着该链路本轮不可用。

`POST /read` 接受 page、link、version、整数 start、end，返回指定的半开字节区间。hex 是实际字节表示，sha256 是整个原页摘要，total 是全页字节数。额度不足返回 429 且不扣额度。已进入传输但实际不可读返回 410，版次改变返回 409，片段超出要约返回 416，均消耗本次区间长度。转发的片段仍引用原设备、世代和原页。每个设备的不同版次是不同的原页，新的封版显式顶替当前覆盖证据，已冻结的旧期原件仍可用于解释旧单。

## 工程资料

`/data/orders.json` 给区段、线路修订、所需设备类别、格点位置与安全级别，级别数值越高优先。last_dispatch 是仍可派工的最后轮，需同时符合船班还接受预约的限制。只使用已知轮次不晚于当前轮的工程修订。线路修订中 affected 是涉及的区段，在这些区段使用新线号，其他区段继续使用前线号。

`/data/calibration.json` 给原始里程到工程线路的标定锚点，锚点间是分段线性比例。原始度数是一段闭区间，可能从逆向标定映射到工程线。卡片的 round 是可知时间，按设备世代、实际测程和线路修订选择卡片，原始范围不在卡片两端内无有效标定。可接受格点位置为工单格点上下 2 米内，定位闭区间完整落在该范围和同一区段内才算命中。区段左闭右开，末段含终点。单条记录只对应一个格点，交界区两个设备类别须分别覆盖全部点。初始原件没有内置业务判读。

`/data/handoffs.json` 提供现场补证和工程复核撤回。withdraw_observation 的 page、version 和 indexes 指原件中从 0 开始的观测行。补证链接可能在通告后才可取；回程后的原始里程或明确格点按回程单的区段、线号和设备类别登记。

## 船务台

`GET /sailing` 列出 boat 和预约状态。每船时段有可访问的相邻区段 spans、最多核对格点 capacity、锁定轮 locks、出发轮 departs、回程轮 returns。一个区段按剩余待核的格点数占用容量，同一格点缺两个设备类别仍占一个现场核对位置。一次船次可容纳多个合适的区段和预约。

`POST /sailing/request` 的 JSON 含 request（一次写入的稳定请求号）、booking（交班约定的预约号）、slot（船次名）、spans（区段名数组）及整数 demand。零 demand 与空 spans 表示取消。原预约所在船次固定，换船可以要求取消原预约再选择新船。相同 request 必须带原样请求内容，可查 `GET /sailing/result?request=...`。503 可能是在对方已确认后产生。锁定前变更立即入账。锁定后仍可针对已有 booking 申请变更，在船班接受前旧安排仍有约束，出发后不能变更。现场人员用 `POST /sailing/decision` 给变更的 request 和 accept 布尔值。船务台只核预约、路线与容量约束，具体哪些位置尚需复核须由工程值班侧判断。
